# File Map — `terraform-provider-azureacme/`

> **What this is.** The placement contract for the Terraform provider. It describes the **shape** of this subtree and where new artefacts go. Read it when your task touches the provider; otherwise skip it.
>
> **Defers to.** [Root `FILE_MAP.md`](../docs/agent-context/FILE_MAP.md) for cross-cutting decisions.

---

## 1. What this deliverable is

A self-contained **Go module** implementing a Terraform provider with the Terraform Plugin Framework, published to the Terraform Registry as `mantisec/azureacme`. It is a *thin* provider: it manages durable certificate registrations through the service's Entra-protected HTTP API and contains no ACME, DNS or Key Vault logic of its own.

Two facts govern everything below:

- **It is its own Go module.** `go.mod` lives here, not at the repository root, and its module path is the *mirror* repository path (`github.com/mantisec/terraform-provider-azureacme`) because that is where releases are published from. `go build ./...` at the repository root does not reach this code — CI must run Go targets from this directory.
- **Its `docs/` directory is a build artefact.** The Terraform Registry reads provider documentation from `docs/` in the published repository, and tfplugindocs generates it. Project prose never goes there; it goes in `docs/agent-context/` at the repository root.

## 2. Shape

| Path | Holds |
|---|---|
| `main.go` | Provider server entry point and the registry address. Nothing else. |
| `internal/provider/` | The provider itself: provider configuration, every resource, every data source, and their tests. One resource or data source per file. |
| `internal/client/` | The HTTP client for the service API: transport, Entra credential acquisition, retry, 202-and-poll handling, error-code translation. Hand-written; its request/response models are generated. |
| `internal/contracts/` | Generated models and error-code constants derived from [`../contracts/`](../contracts/). Committed, marked generated, regenerated by `go generate` and drift-checked in CI. Never hand-edited. **Every file here is generated, tests included** — `patterns.gen_test.go` is the generated self-test that proves each emitted regex constant matches its own examples from `../contracts/primitives/primitives.yaml`. Do not put a hand-written test in this directory: the drift check requires a `DO NOT EDIT` marker on every `.go` file it finds here, so a hand-written one fails the marker check. A hand-written test *about* the generated package belongs in the package that consumes it. |
| `internal/customtypes/` | The three semantic-equality framework types of `terraform-provider-contract.md` §4 — `dnsname.String`, `armid.String`, `rfc3339.String` — one package each, plus one external-test package holding their shared equivalence-class table. They are **schema fragments**, not primitives: `dnsname` decides EQUALITY and delegates every normalisation question to `internal/primitives`. |
| `internal/fakeservice/` | The scriptable in-process fake service (`PROV-FAKE-SERVICE-HARNESS`). An `httptest.Server` with real registration and operation state, plus a rule engine that produces the responses no real service will produce on demand — a `302` to a sign-in page, an HTML `200`, an untyped `404`, a `404` stamped with a different `service_instance_id`. Test-only, but **not** in a `_test.go` file: the acceptance suite in `internal/provider/` imports it. **Half of it is GENERATED: `routes.gen.go`** — the operation ids, the dialled paths, the declared response statuses and the precondition rule — is emitted from [`../contracts/api/openapi.yaml`](../contracts/) by `../contracts/tools/generate.py` and drift-checked by `../contracts/tools/check_drift.py`, which names it one by one because this is not one of the two generated *package* directories. Never hand-edit it. The split is deliberate: what the CONTRACT decides is generated, and what the contract does not describe — the state machine, the scenario knobs, the rule engine — is written. A fake hand-written from the same prose as the client agrees with the client and with nothing else. It lands here rather than in `internal/contracts/` because the fake is test-only and `internal/contracts/` is compiled into the shipped provider. |
| `internal/primitives/` | The Go half of the shared cross-language primitives: identifier normalisation, the namespace grammar, `destinationHash`, the pinned Public Suffix List loader, the wire formats. **Hand-written**, not generated (`contracts-and-codegen.md` §7.3), and the *only* place in this module that may define any of them (§7.4). Its tests read the shared vector corpus in [`../contracts/primitives/vectors/`](../contracts/) at test time — never embedded, never shipped, and so does the PSL loader itself until `CI-PACKAGE-RUNTIME-DATA-FILES` gives the snapshot a shipped home. |
| `internal/contractschema/` | The deliberately small **JSON Schema reader** that `internal/policycontract/` and `internal/cataloguecontract/` share. Hand-written, because a published provider's dependency set is part of what consumers install and a JSON Schema library would be carried for tests alone. It is a package rather than a `_test.go` file for one reason: `contracts/policy/` and `contracts/catalogue/` are both cross-referencing sets of `*.schema.json` files, a `_test.go` file cannot be imported, and a validator copied into the second suite is a validator that drifts — which is the failure the whole cross-language harness exists to prevent. Nothing that ships imports it, so it is not linked into the binary. It fails on any keyword it does not implement, so it can be wrong but cannot be quietly weaker than the Python side. |
| `internal/policycontract/` | The Go half of the **policy-document** contract conformance: the golden examples in [`../contracts/policy/examples/`](../contracts/), validated against [`../contracts/policy/*.schema.json`](../contracts/) by this module's own suite, so the Go and Python readings of one document cannot diverge silently. **Test-only** — `doc.go` carries the package clause and nothing else, and nothing here is imported by shipped code. Same reading rule as `internal/primitives/`: the contract files are read at test time, never embedded and never shipped. The reader itself is `internal/contractschema/`, shared with the catalogue suite. |
| `internal/apicontract/` | The Go half of the **API golden-example** conformance: the documents in [`../contracts/api/examples/`](../contracts/), validated against the schemas in [`../contracts/api/openapi.yaml`](../contracts/), so the Go and Python readings of one wire document cannot diverge silently. The API sibling of `internal/policycontract/`, with the same shape (`doc.go` plus `_test.go` files, nothing imported by shipped code, contract files read at test time) and its own reader, because the policy plane is a set of cross-referencing schema *files* while the API schemas are one YAML document whose `$ref`s are all document-local. Both readers fail on a JSON Schema keyword they do not implement, so the Go side can be wrong but cannot be quietly weaker than the Python side. |
| `internal/cataloguecontract/` | The Go half of the **catalogue-document** conformance: the golden documents in [`../contracts/catalogue/examples/`](../contracts/), read against [`../contracts/catalogue/*.schema.json`](../contracts/) through the shared reader in `internal/contractschema/`. The catalogue sibling of `internal/policycontract/`, same shape and same reason. One file in it is not about shape at all: `destination_hash_test.go` recomputes every `destinationHash` the corpus records from the vault id and certificate name beside it, because a schema sees only sixty-four hex characters and cannot tell a derived hash from an invented one. **Test-only**; contract files read at test time, never embedded. |
| `examples/` | tfplugindocs input. Layout is fixed by the tool: `examples/provider/provider.tf`, `examples/resources/azureacme_<type>/resource.tf` (plus `import.sh` where import is supported), `examples/data-sources/azureacme_<type>/data-source.tf`. |
| `examples/two-stage-bootstrap/` | The **one directory here the tool does not read**, and the exception is required by `terraform-provider-contract.md` §12 item 2, which names this exact path. It is a two-root-module worked example (`stage-1-platform/`, `stage-2-certificates/`) showing why the provider's `endpoint` cannot come from a resource in the same configuration. tfplugindocs ignores it, so it reaches the registry only through the prose that links it — `templates/guides/two-stage-bootstrap.md.tmpl`. A second non-tool directory needs a better reason than "it is also an example"; the tool-read paths above are where a snippet belongs. |
| `templates/` | tfplugindocs templates. Add one **only** when the default rendering for a specific page is genuinely insufficient; an empty or pass-through template is noise. `templates/index.md.tmpl` earns its place: it carries the guide index, which has no default rendering and which the registry has no other way to surface. **`templates/guides/error-reference.md.tmpl` is the one exception to "hand-authored": it is GENERATED** by `../contracts/tools/generate.py` from `../contracts/errors/error-codes.yaml` (`terraform-provider-contract.md` §12 item 7) and carries a `DO NOT EDIT` marker inside its front matter. Change the taxonomy and run `make contracts-generate`; a hand edit is reverted by `make contracts-verify`. The `.md.tmpl` extension is load-bearing beyond tfplugindocs — `contracts-verify.yml` carries `paths-ignore: '**.md'`, so a plain `.md` name would skip the workflow that runs the drift check. |
| `templates/guides/` | tfplugindocs guide sources — one file per guide required by `terraform-provider-contract.md` §12, and the **only** place registry prose is written. A guide has no default rendering, so the template **is** the page: tfplugindocs renders `<name>.md.tmpl` to `docs/guides/<name>.md` byte-for-byte when it carries no template action. A new guide is a three-part change: the template, a row in `templates/index.md.tmpl`'s guide table, and regenerated `docs/` — `internal/provider/docs_test.go` fails on any of the three being missing. |
| `docs/` | **Generated.** Registry documentation, produced by `make provider-docs` (tfplugindocs, pinned in `tools/`). Committed because the registry reads it from the published repository; never hand-edited. CI regenerates and diffs it, so it goes stale the moment a schema description, an `examples/` snippet or a `templates/` page changes without a regeneration. |
| `tools/` | `tools.go` build-tag file pinning developer tools (tfplugindocs, the model generator) so their versions are in `go.sum`. The `tools` build tag keeps them out of `go build`, `go vet` and `go list -deps`, so a documentation generator never enters the shipped dependency graph or the Azure data-plane guard's view. |
| `.github/workflows/` | **Workflows that run in the MIRROR repository, not in the monorepo.** GitHub reads `.github/workflows/` only at a repository *root*, and in the monorepo this one is three levels down — inert. It becomes live after the release subtree-pushes this directory into `mantisec/terraform-provider-azureacme`, where this directory *is* the root (`release-engineering.md` §4.1). It is authored here because a mirror is a publication target, not a development home: the subtree push is force-based, so a workflow committed only in the mirror is destroyed by the next release, silently. `release.yml` is the GoReleaser job §10.4 places "on a mirror bare tag" — it supplies the Go toolchain, the GPG key and the release identity; the asset contract itself is `.goreleaser.yml`. The monorepo half of the same release is `../.github/workflows/provider-release.yml`. `../.github/scripts/check_workflow_hygiene.py` scans this directory too, applying its per-file rules; the §10.2 routing table and the six-prefix naming rule are not applied, because both describe the monorepo's workflow set and a mirror holds one deliverable. |
| `LICENSE` | Byte-identical copy of the root `LICENSE` (MPL-2.0). The mirror is a subtree split of this directory, so the root file never reaches it; without this copy the public source and every release archive would carry no licence. `contracts/tools/check_licence.py` fails if the two differ. |
| `.gitignore` | Ignores GoReleaser's `dist/`. In the mirror this directory is the repository root and the monorepo's root `.gitignore` does not exist, so an untracked `dist/` would stamp every release binary `vcs.modified=true`. |
| `.goreleaser.yml` | Release build and GPG-signing configuration. Signing keys come from CI secrets. Runs in the mirror, where `.ProjectName` resolves to `terraform-provider-azureacme` — the naming the Registry requires. |
| `CHANGELOG.md` | Consumer-facing release notes for this provider's semver line. Distinct from `docs/agent-context/changelogs/`. |

## 3. Where does X go?

| I want to add… | Goes in | Notes |
|---|---|---|
| A resource | `internal/provider/<name>_resource.go` | Register it in `Resources()`. `azureacme_certificate` is split across `certificate_resource{,_schema,_state,_read,_plan,_wait,_validators}.go` because one file would be ~2,500 lines; the split is by CONCERN, and the `Read` decision table in particular is worth its own file and its own test file. |
| A scenario the fake cannot yet produce | `internal/fakeservice/` | Add a `Behaviour` knob or a `Respond*` canned response. Never reach for a bespoke `httptest.Server` in a test file: the fake is where the contract's shape is asserted once. |
| A route, status code or precondition rule the fake should know about | Nowhere here — `../contracts/api/openapi.yaml`, then `make contracts-generate` | `internal/fakeservice/routes.gen.go` is generated. Adding a path to the switch in `handlers.go` without the contract change gives the fake an address the service does not serve, which is exactly the shared-wrong-assumption failure the generation exists to prevent. An operation the contract declares and the fake does not yet model reaches `notImplemented` and fails the test loudly — that is the signal to add the handler. |
| A data source | `internal/provider/<name>_data_source.go` | Register it in `DataSources()`. A data source must never cause issuance, renewal or an ACME order. |
| Shared schema fragments or plan modifiers | `internal/provider/` alongside the users | Promote to `internal/provider/schemaext/` only once a third consumer appears. |
| A change to how the provider talks to the service | `internal/client/` | Regenerate `internal/contracts/` if the API surface changed; the OpenAPI document in `../contracts/api/` is the source, and it changes first. |
| A unit test | Beside the code, `<file>_test.go` | Must pass with no network, no Azure credentials and no `TF_ACC`. |
| A normalisation, namespace, hash, PSL or timestamp rule | Nowhere — `internal/primitives/` already has it | Two languages must agree on the exact output and a divergence is silent. A second definition is a defect and a CI grep fails it. |
| An assertion about a **policy document's shape** (`contracts/policy/`) | `internal/policycontract/<name>_test.go` | The Go side of a contract both languages read. Add the golden example and its manifest entry in `contracts/policy/examples/` first — the fixture is the contract, this package is one of its two readers. Never assert the shape in a hand-copied literal here. |
| An assertion about an **API document's shape** (`contracts/api/`) | `internal/apicontract/<name>_test.go` | Same rule, other contract. Add the golden request or response and its manifest entry in `contracts/api/examples/` first; this package is one of its two readers, the other being `functionapp-azureacme/tests/api/test_error_details_and_examples.py`. A fixture added to one language only is not a fixture. |
| An assertion about a **catalogue document's shape or a value derived from one** (`contracts/catalogue/`) | `internal/cataloguecontract/<name>_test.go` | Same rule, third contract. Add the golden document and its manifest entry in `contracts/catalogue/examples/` first; this package is one of its two readers, the other being `functionapp-azureacme/tests/catalogue/`. A derived identifier (`destinationHash`, `issuanceHash`) is asserted by RECOMPUTING it from the document's own inputs — never by comparing it with a literal copied out of the fixture, which asserts only that copy-paste worked. |
| An acceptance test | Beside the resource, `<name>_resource_acc_test.go` | `_acc_test.go` is the mandatory suffix — it makes the split greppable and lets CI run the two tiers separately. Use `resource.Test` (which skips unless `TF_ACC` is set) and a `testAccPreCheck` that fails clearly when required environment variables are missing. |
| An example snippet | `examples/…` at the exact tfplugindocs path | The path determines which generated page the snippet lands in. A new resource without an example produces a docs page with no usage section. |
| A guide page (a topic with no schema to attach it to) | `templates/guides/<name>.md.tmpl`, plus a row in `templates/index.md.tmpl` | The template IS the page. §12 of `terraform-provider-contract.md` is the list of guides this provider owes; a guide the index does not link is unreachable from the registry, which is why `docs_test.go` asserts the link. |
| Documentation for a resource | The schema's `Description` / `MarkdownDescription`, then regenerate | Never edit `docs/` directly. |
| A CI step the **mirror** must run (anything reacting to the bare `vX.Y.Z` tag) | `.github/workflows/` here | Not `../.github/workflows/`: that set runs in the monorepo, where no bare tag ever exists. Anything reacting to a *prefixed* monorepo tag goes there instead — `provider-release.yml` is the split. |
| A row on the registry's error reference page | Nowhere here — `../contracts/errors/error-codes.yaml` | The page is generated from the taxonomy. Editing `templates/guides/error-reference.md.tmpl` is reverted by the contract drift check; operator remediation prose for a code is a runbook, not a registry page. |

## 4. Conventions

- **A new resource or data source is a three-part change**: the Go file, the `examples/` snippet, and regenerated `docs/`. CI fails if `docs/` is stale.
- **`docs/` is regenerated by `make provider-docs`, never written.** The generator is tfplugindocs, pinned in `tools/tools.go` so every contributor and every CI run emits identical bytes. Its inputs are the schema descriptions, `examples/` and `templates/` — and `templates/guides/error-reference.md.tmpl` is itself generated from `../contracts/errors/error-codes.yaml`, so a taxonomy change is `make contracts-generate && make provider-docs`, two regenerations in that order. `provider-ci.yml` runs the generator and diffs the tree, so a stale page fails the pull request rather than reaching the registry.
- **The error reference is generated, not written.** `templates/guides/error-reference.md.tmpl` comes from `../contracts/errors/error-codes.yaml` via `../contracts/tools/generate.py`, and `../contracts/tools/check_drift.py` reverts a hand edit. A table of every error code transcribed by hand is a second source of truth that goes stale silently, and a reader who trusts a stale `actor` column escalates to the wrong team.
- **No Azure data-plane SDK may ever be linked.** `internal/provider/dependency_guard_test.go` runs
  `go list -deps ./...` and fails on `azsecrets`, `azcertificates` and the rest of the Azure data plane.
  A Key Vault certificate's sibling secret value is the PKCS#12 bundle **including the private key**, so
  a "just fetch the secret so users can see the chain" convenience would write private keys into every
  consumer's state file and every archived plan. `azidentity` is not covered — the credential chain needs it.
- **Never expose secret material as an attribute.** No private keys, PFX bytes, ACME account keys or access tokens — marking a field sensitive hides display, it does not keep the value out of state.
- **Read must not be destructive or presumptuous.** Authentication failure, service outage and expired certificate are three different things, and none of them means "the registration is gone" — do not remove the resource from state for any of them.
- **Ordinary renewal must never plan a replacement.** Renewal changes the certificate version, not the registration identity.
- **Acceptance tests use ACME staging only**, against a disposable service instance. They must clean up the registrations they create even when they fail.
- **Tests stay co-located.** Go's tooling, coverage and package-internal access all assume it. The repository's cross-deliverable tests live in [`../integration-tests/`](../integration-tests/); nothing from this subtree moves there.
